What AWS documents and how this repository responds

Duplicate events must be safeS3 notifications are at least once and rare duplicates can occur.Deterministic record identity plus conditional DynamoDB write.
Event order is limitedS3 does not guarantee notification order; sequencers compare events only for the same object key.The schema records the sequencer and does not claim global ordering.
Metadata can be read without downloading the fileHeadObject returns object metadata with no response body.The Lambda calls head_object and never downloads the full object.
Failures can be retried and quarantinedLambda supports maximum event age, 0–2 retries, and failure destinations.One-hour event age, two retries, and an encrypted SQS destination.
Duplicate writes can be rejectedDynamoDB supports conditional puts with attribute_not_exists.The put only succeeds when RecordId is absent.
The upload bucket should not be publicS3 provides four Block Public Access controls and recommends enabling them where public access is unnecessary.All four controls are enabled and ACLs are disabled.
Accidental data changes need a recovery pathDynamoDB PITR provides managed continuous backups and recovery points.PITR is enabled, and the table is retained on stack deletion.

What verification means

Legitimate architecture is not the same as an inflated employment claim

What these sources establish

  • The event-driven pattern is supported by AWS.
  • The failure, retry, destination, and conditional-write mechanisms are real platform features.
  • The public implementation follows documented service behavior.
  • The security and retention controls are valid CloudFormation concepts.

What these sources do not establish

  • That this repository contains confidential Amazon code.
  • That the internship involved production customer ownership.
  • That a live AWS stack is currently deployed under Bradley's account.
  • That certification alone equals production experience.
