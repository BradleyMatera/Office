AWS Evidence Design System · version 1.0.0

A technical portfolio system built for trust before decoration

This is the shared visual and content contract for the workflow, writing, proof, and verified-source pages. It defines tokens, components, illustration rules, accessibility acceptance criteria, SEO requirements, and the language boundaries that prevent the site from drifting into unsupported claims.

Principles

Five rules guide every page

01

Verified before impressive

Proof, code, source links, official documentation, and scope boundaries come before visual spectacle.

02

Operational, not fictional

Graphics resemble systems, data, runbooks, and dashboards instead of fake live-account screenshots.

03

Plain language, real depth

Recruiters can understand the headline while engineers can keep drilling into implementation detail.

04

Accessible by default

Keyboard access, contrast, reduced motion, descriptive images, logical headings, and responsive layouts are release requirements.

05

Scope is a component

What the internship did not include is displayed with the same design quality as the positive evidence.

Native FAQ disclosure

Why use native details and summary?

They provide keyboard and screen-reader behavior without adding JavaScript or custom state management.

Illustration language

Every graphic explains a system or decision

First-party SVGs avoid copied service logos and unverified screenshots. Each graphic includes internal title and description elements plus surrounding explanatory text.

Operational console

Logs, event flow, function logic, metadata records, and a repeated observe-isolate-verify-document loop.

Cost radar

Resources, thresholds, cleanup state, request volume, duration, storage, and retention.

Grounded knowledge

Recruiter questions move through verified source material before a final answer is presented.

Accessibility acceptance

A release is not done when it only looks good

Required before release

  • Unique title, description, canonical URL, and visible h1.
  • Skip link and main landmark.
  • Logical heading levels.
  • Descriptive alternative text for meaningful images.
  • Visible keyboard focus and keyboard-operable controls.
  • Responsive behavior without full-page horizontal scrolling.
  • Reduced-motion and forced-colors handling.

Production checks

  • JSON-LD parses successfully.
  • Local assets and links resolve.
  • Robots and sitemap agree.
  • Pages health workflow can fetch critical URLs.
  • Python, SAM, and site validation pass together.
